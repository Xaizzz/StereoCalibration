ИНЖЕНЕРНО-МАТЕМАТИЧЕСКОЕ ОПИСАНИЕ ПРОГРАММНОГО КОМПЛЕКСА STEREOCALIBRATION
(каталог calibr/) — расширенная редакция для отчётности / дипломной работы
================================================================================

Назначение документа
--------------------
  Текст описывает принцип работы, математические модели, численные методы, пути
  сбора данных, отладку и ограничения по точности — строго по реализации в коде
  основного пользовательского контура (MainForm → MainFormController → сервисы
  камер и геометрии → Scene3DUserControl). Параллельные ветки (например
  TriangulationService с Models.CalibrationResult) упоминаются только там, где
  важно не перепутать типы при интеграции.

  С практики биоинженерии: цепочка «стереозрение → облако опорных маркеров на
  ткани → деформируемая цифровая модель поверхности → адаптация траектории
  нанесения» соответствует задаче навигации печати/аппликатора по неровной,
  деформируемой поверхности с опорой на маркеры и (опционально) CAD-модель раны.

--------------------------------------------------------------------------------
0. КОНТЕКСТ ДЛЯ БИОИНЖЕНЕРНОГО ДИПЛОМА
--------------------------------------------------------------------------------
  Измерение: стереопара даёт 3D-координаты ArUco-маркеров в первой камере (мм),
  после калибровки с известным масштабом доски. Это привязывает пиксельные
  измерения к миллиметрам — необходимое условие для медицинско-технических
  допусков на сцене.

  Регистрация модели: модель раны (OBJ) сбивается с измерениями через оценку
  подобия (масштаб, поворот, перенос) и затем нелинейную деформацию (RBF/TPS),
  чтобы объём сетки следовал за измеренными маркерами при деформации ткани.

  Адаптация печати: траектория в плоскости G-кода (XY) «натягивается» на
  текущую 3D-поверхность (маркеры или mesh) через кусочно-линейную интерполяцию
  в параметрической 2D-проекции (барицентрики по треугольникам) и смещение
  вдоль локальной нормали — инженерный компромисс между точностью и скоростью
  пересчёта в реальном времени.

2. ГЛОССАРИЙ СИСТЕМ КООРДИНАТ И ОБОЗНАЧЕНИЙ
--------------------------------------------------------------------------------
  СК_камеры_1 (OpenCV):
    Результат триангуляции ImageProcessingService: (X,Y,Z) в миллиметрах.
    Фильтр глубины использует компоненту Z: MinDepthMm ≤ Z ≤ MaxDepthMm.
    В документации к калибровке: вектор T стереопары также в мм.

  Визуальная_СК_сцены (Scene3DService + Helix):
    Начало в центре стереопары; ось X вдоль базовой линии; Y «вперёд» (биссектриса
    оптических осей в СК камеры 1); Z «вверх» (усреднённая ось «ап» камер).
    Преобразование: ConvertFromCamera1ToScene / Matrix3D Camera1ToScene.

  Сырые / сглаженные:
    MarkerPositionsCamera1RawMm — по последнему кадру триангуляции (после
    фильтра ImageProcessing, без экспоненциального сглаживания сцены).
    MarkerPositionsCamera1Mm — после сглаживания Scene3DService (другой α,
    чем у WoundModelService для деформации).
    MarkerPositions — визуальная СК для отрисовки.

  Про матрицы E и F:
    StereoCalibrate записывает существенную E и фундаментальную F. В текущем
    контурe триангуляции маркеров используются K, дисторсия, R, T и конструкция
    P1,P2 для TriangulatePoints; E/F не подставляются в этот шаг, но сохраняются
    в JSON для полноты описания стереосистемы и возможных будущих проверок.

3. КАЛИБРОВКА СТЕРЕОПАРЫ — МАТЕМАТИКА, ДАННЫЕ, МЕТРИКИ ТОЧНОСТИ
--------------------------------------------------------------------------------
3.1. Модель камеры (пинхол)
  Внутренние параметры K (3×3) в нотации OpenCV / Models.CalibrationResult:
        [ fx   0  cx ]
    K = [  0  fy  cy ]
        [  0   0   1 ]
  fx, fy — фокусные расстояния в пикселях; (cx,cy) — главная точка.
  DistCoeffs длиной 5: [k1, k2, p1, p2, k3] — радиальная и тангенциальная
  дисторсия в формулировке, принятой CalibrateCamera при пяти коэффициентах.

3.2. Стереомодель
  Связь однородных 3D-точек в СК камеры 1 и 2 (как используется далее):
    X̃₂ ∼ R·X̃₁ + T   (в коде Scene3DService для вектора T в Евклидовых coords).
  После индивидуальной калибровки каждой камеры StereoCalibrate с FixIntrinsic
  уточняет внешние R, T при фиксированных K и дисторсии.

3.3. Источник калибровочных данных
  Файл: Services/StereoCalibrationService.cs
  Пары изображений: каталоги cam1/{folder}, cam2/{folder}, одинаковое число
  файлов, не менее 10 успешных пар с одновременно найденной доской на обеих камерах.
  patternSize и squareSize задаются конструктору; в MainFormController по умолчанию
  внутренний размер паттерна 9×6 углов, squareSize = 8.5 мм (проверить актуальные
  константы в коде при смене железа).

3.4. Объектные 3D-точки шахматницы
  Индексы клетки: i ∈ [0, Height), j ∈ [0, Width)
    X_obj = j·squareSize,  Y_obj = i·squareSize,  Z_obj = 0.
  Плоскость доски — эталон масштаба: ошибка squareSize напрямую масштабирует T
  и все последующие миллиметровые измерения.

3.5. Извлечение углов на изображении
  FindChessboardCorners(..., ChessboardFlags.FastCheck).
  Уточнение: CornerSubPix на grayscale, окно 11×11, TermCriteria(Eps|MaxIter,
  maxIter=30, eps=0.1). Субпиксельное уточнение снижает дисперсию образа точки
  и улучшает условность задачи CalibrateCamera.

3.6. Оценка параметров
  Две независимые Cv2.CalibrateCamera(..., CalibrationFlags.None,
  TermCriteria(Eps|MaxIter, 100, 1e-6)).
  Скаляр err1, err2 — средние reprojection error (как возвращает OpenCV).
  Если err > 1.0 пикселей — Debug-предупреждение (автоотказ не делается).

  Cv2.StereoCalibrate(..., CalibrationFlags.FixIntrinsic) → R, T, E, F, Error.
  Поле Services.CalibrationResult.Error — стерео error OpenCV (опирается на те же
  3D-3D/репроекции; интерпретировать как «качество согласования пары» при записи
  в отчёт, сравнивая с документацией OpenCV для используемой версии).

3.7. Центр второй камеры в СК первой
  Для оптического центра камеры 2 в её собственных координатах X₂=0:
    0 = R·C₂ + T  ⇒  C₂ = −Rᵀ·T.
  Реализация в CalculateSecondCameraCenter умножает компоненты T на строки Rᵀ.

3.8. Сохранение и автозагрузка
  MainFormController при старте: LoadCalibrationResult("calibration_result.json").
  После успешной калибровки: SaveCalibrationResult → тот же файл в рабочем каталоге.
  JSON: Newtonsoft, поля Services.CalibrationResult — см. §3.10.

3.9. Источники погрешности калибровки (для раздела диплома о точности)
  - Неточность размера клетки и планарности физической доски.
  - Синхронизация пар кадров (если пары не строго одновременны — движение доски).
  - Качество углов: шум, смаз, разрешение (в приложении захват 640×480).
  - Модель дисторсии (5 коэффициентов) может быть недостаточной для сильной
    дисторсии дешёвых линз.
  - FixIntrinsic фиксирует K при стереоэтапе: ошибки монокалибровки переносятся.

3.10. Структура calibration_result.json (Services.CalibrationResult)
  CameraMatrix1, CameraMatrix2: double[,] 3×3
  DistCoeffs1, DistCoeffs2: double[5]
  R: double[,] 3×3
  T: double[3]
  E, F: double[,] 3×3
  Error: double

3.11. Дублирование типа Models.CalibrationResult
  Расширенная модель в Models/ (поля ImagePairsCount, CalibrationDate, IsValid(),
  GetQualityDescription с порогами Error 0.5 / 1.0 / 2.0) используется альтернативным
  CalibrationService. Основной runtime-путь диплома — Services.CalibrationResult.

5. ДЕТЕКЦИЯ ARUCO И ДВУМЕРНАЯ УСТОЙЧИВОСТЬ
--------------------------------------------------------------------------------
5.1. Профиль
  ArucoDetectionProfile: словарь Dict6X6_250 (до 250 ID, маркер 6×6 бит).
  DetectorParameters: широкий диапазон AdaptiveThreshWinSize 3…35 шаг 8,
  Min/MaxMarkerPerimeterRate, CornerRefineMethod.Subpix (окно 5, до 30 итераций,
  min accuracy 0.05), PerspectiveRemove*, ErrorCorrectionRate = 0.6 и др.
  Смысл: повышение recall на сложной кожной/глянцевой поверхности ценой CPU.

5.2. Память и stale-ID
  DetectionMemoryFrames = 3 — подстановка последнего надёжного положения маркера.
  RoiPaddingPixels = 70 — расширение ROI вокруг прошлых углов для ускорения/стабильности.
  staleIds: если позиция взята из памяти, ID не триангулируют — защита от 3D
  на «застывших» 2D-углах при рассинхроне пары камер.

--------------------------------------------------------------------------------
6. ТРИАНГУЛЯЦИЯ МАРКЕРОВ — ЛИНЕЙНАЯ АЛГЕБРА И ПРАКТИКА
--------------------------------------------------------------------------------
6.1. Сопоставление
  Одинаковый ArUco ID в ids камеры 1 и 2; отбрасывание stale.

6.2. Устранение дисторсии
  UndistortPoints для четырёх углов маркера на каждой камере → нормализованные
  плоские координаты (фактически на плоскости z=1 в нормализованной камере).

6.3. Проекционные матрицы в коде
  P1 = [ I₃ | 0 ],  P2 = [ R_stereo | T_stereo ]  (обе 3×4),
  где R,T из результата стереокалибровки. Это согласовано с подходом «normalized
  coordinates + эксплицитная экзацентрическая пара» без повторного умножения на K
  в P1,P2 (K уже «вшита» в undistorted points в терминологиях OpenCV).

6.4. TriangulatePoints
  OpenCV решает переопределённую систему по двум лучам; вывод — однородные
  координаты (4×N). Декартовы: x=X/W, y=Y/W, z=Z/W при |W|>1e−10.

6.5. Центр маркера
  Усреднение 3D по четырём углам после триангуляции — сознательная мера против
  смещения при наклоне маркера (средний 2D-центр ≠ проекция 3D-центра).

6.6. Валидация и временная связность
  Диапазон координат ±20000 мм; глубина Z ∈ [30, 5000] мм; межкадровый скачок
  между принятыми позициями одного ID ≤ 220 мм, если кадры разделены не более чем
  на 8 итераций триангуляции. PruneHistory удаляет историю старше 120 кадров.
  Пустой словарь события при отсутствии маркеров в одной из камер включает TTL
  в Scene3DService (см. §7).

6.7. Замечание о точности в глубину
  Относительная ошибка глубины в стерео масштабируется с квадратом расстояния и
  обратно базовой линией и качеству калибровки (классическая оценка порядка
  σ_Z ∝ Z²/(B·fx) в упрощённых моделях). В дипломе это связывают с выбранным
  640×480 и базой |T| из calibration_result.json.

--------------------------------------------------------------------------------
7. СГЛАЖИВАНИЕ И ОТОБРАЖЕНИЕ МАРКЕРОВ (Scene3DService)
--------------------------------------------------------------------------------
7.1. Экспоненциальное сглаживание первого порядка
  d = ||P_prev^smooth − P_meas||_2
  α = 0.65 если d > 80 мм, иначе α = 0.25
  P_smooth ← P_prev + α·(P_meas − P_prev)  покомпонентно.
  Физический смысл: малый α подавляет дрожание шумной триангуляции; большой α
  уменьшает лаг при быстром перемещении маркированного тела.

7.2. TTL маркера
  MissingFramesBeforeRemoval = 10 кадров UpdateMarkerPositions без нового замера ID.

7.3. Визуализация (Scene3DUserControl) — оптимизация WPF
  Полигон «крышки» по маркерам: одна MeshGeometry3D заменяется, а не тысячи мелких
  объектов (комментарий в коде) — снижение нагрузки на визуальное дерево WPF.
  Троттлинг: поверхность ≤1 раз / 300 мс и при |Δпозиции|>8 мм; стабилизация
  топологии 250 мс после смены набора ID; подписи/таблица/линии 100–500 мс.
  MaxSurfaceMarkers = 24 — верхняя граница числа узлов полигона по маркерам.

--------------------------------------------------------------------------------
9. ВЫРАВНИВАНИЕ И ДЕФОРМАЦИЯ (WoundModelService + RbfDeformationService)
--------------------------------------------------------------------------------
9.1. Захват опоры CaptureReference
  - Стабильность набора привязок: StableFramesForReferenceCapture = 12 кадров с
    одинаковой сигнатурой видимых маркеров (см. FeedCaptureStability / SealCaptureStability).
  - Масштаб-кандидаты AutoScaleCandidates × similarity: подбор минимума
    RMSE(aligned_model_ctrl → camera_ctrl) + штраф за |candidate·scale| вне
    [0.22, 5] (логарифмический штраф веса CaptureCombinedScalePenaltyWeight).
  - SimilarityTransform.Estimate — см. §9.2.
  - RbfDeformationService.Prepare(vertices, controlPoints) на выровненной сетке.
  - bias векторы observed_vs_aligned маркеров и RMSE — количественная метрика
    «фантом vs CAD» на первом кадре.
  - Нормаль поверхности по маркерам EstimateSurfaceNormal (§9.4).

9.2. Оценка подобия (Procrustes / Umeyama-подобная схема в коде)
  Центроиды c_src, c_tgt; центрированные точки sᵢ, tᵢ.
  Ковариантная матрица H₃ₓ₃: H[p,q] = Σᵢ (sᵢ−c_src)ₚ·(tᵢ−c_tgt)q — это сумма внешних
  произведений центрированных векторов (эквивалент записи Σ sᵢ'tᵢᵀ).
  QuaternionToMatrix: из кватерниона q по стандартной формуле вращения 3×3.
  Кватернион оценивается EstimateRotationQuaternion: строится симметричная 4×4
  матрица N(H) и до 32 итераций нормализованного умножения (итерация на главный
  собственный вектор в духе степенного метода).
  Масштаб:
    S = Σᵢ ||sᵢ||² ,  N = Σᵢ ⟨tᵢ, R·sᵢ⟩,  s = N/S (если S мала → 1).
  Перенос: t = c_tgt − s·(R·c_src).
  Применение: p' = s·R·p + t.

9.3. Робастная оценка жёсткого движения TryEstimateRobustGlobalMotion
  Периферийные маркеры для оценки жёсткой позы: индексы с расстоянием от центроида
  не меньше медианного радиуса (BuildPeripheralMarkerIndicesForRigidFit) — идея:
  центральные маркеры могут вести себя не как жёсткое тело из-за местного изгиба.
  Если периферийных ≥4: перебор троек (комбинации), для каждой тройки Similarity
  Estimate между референсными наблюдёнными и текущими точками; отбор inlier по
  порогу RigidInlierThresholdMm (34 мм на периферии); скор
    score = RMSE_inliers + |scale−1|·RigidScalePenaltyWeight (12).
  Лучшая тройка → уточнение transform = Estimate по всем индексам inlier.
  Внутренние маркеры допускают больший остаток (RigidInlierInnerMarkerThresholdMm = 95).
  Это близко по духу к RANSAC с полным перебором троек на ограниченном наборе.

9.4. Оценка нормали поверхности по облаку маркеров EstimateSurfaceNormal
  Центр облака c; матрица вторых моментов (дисперсии/ковариации) для (x,y,z):
    xx, xy, xz, yy, yz, zz — суммы по точкам относительно c.
  Нормаль строится через максимальные детерминанты 2×2 подматриц (устойчивый
  способ получить вектор, сопряжённый наименьшему собственному значению ковариации;
  при вырождении — fallback: векторное произведение трёх точек; иначе (0,0,1)).

9.5. Фильтрация управляющих точек перед RBF (TryBuildPhysicallyFilteredControlPoints)
  После оценки globalMotion clamp масштаба при отклонении от 1 (MaxRigidScaleChange);
  жёсткий отказ при |scale−1| > MaxRigidScaleHardReject (0.45).
  Сравнение нормали: dot(expected, current) ≥ MinSurfaceNormalDot (0.45), иначе freeze.
  rigid RMSE по периферии ≤ MaxRigidRmseMm (35).
  Для каждой точки: residual = current − rigidPredicted; разложение на нормаль и
  касательную; dead-zone NonRigidResidualDeadZoneMm; лимиты MaxNormalResidualMm,
  MaxTangentialResidualMm с InnerMarkerNonRigidBoost у центра; смешение
  NonRigidDeformationBlend / NonRigidNormalBlend; выбросы — ужесточённые ветки.

9.6. RbfDeformationService (математика TPS-типа в 3D)
  Нормализация контрольных точек: origin = центр bbox маркеров; scale = 1/diagonal.
  Для точки p: p̃ = (p − origin)·scale.

  Ядро: φ(r) = r² ln r при r>ε, иначе 0 (ε=1e−10).

  Неизвестные коэффициенты w ∈ ℝⁿ, n = число маркеров, и a ∈ ℝ⁴ (affinely вместе
  с базисом [1,x,y,z] в нормализованных координатах) из условий интерполяции смещений
  на маркерах. Матрица (n+4)×(n+4) симметрична по блокам K (ядро между контрольными)
  плюс блоки полиномиальных ограничений; диагональ K регуляризуется 1e−6, полиномиальная
  часть 1e−8 — улучшение численной устойчивости при почти вырожденных конфигурациях.

  Решение: явное инвертирование методом Гаусса с выбором главного элемента (Invert).

  При каждом Apply: для оси RHSᵢ = Δкоординаты маркера_i; coeff = A⁻¹·RHS.
  Смещение вершины: сумма базисных функций × coeff (предвычисленный _vertexBasis).

  Сложность Prepare: O((n+4)³) на инверсию + O(V·n) на базис вершин V.
  Apply: O(V·(n+4)).

9.7. ApplyPhysicalVertexConstraints (ограничение деформации объёма)
  Для каждой вершины ограничивается величина отклонения от «жёсткой» позы:
  влияние маркеров exp(−dist/VertexResidualDecayDistanceMm), профиль по радиусу
  от центра маркеров (CenterResidualFactor, CenterEdgeProfilePower), отдельные
  капы на нормальную и касательную составляющую; шаг за кадр MaxResidualStepPerFrameMm,
  сглаживание ResidualTemporalBlend между кадрами. Это снижает артефакты «шипов»
  между редкими маркерами и стабилизирует визуал при шуме.

9.8. События Diag(...) — типы для JSONL-журнала (WoundModelService)
  reference_reset_manual — сброс опоры вручную.
  model_loaded — загрузка OBJ (метаданные).
  deformation_skipped_motion_gate — пропуск кадра из-за гейта движения/времени.

  mesh_frozen — заморозка геометрии и причина.

10. АДАПТАЦИЯ ТРАЕКТОРИИ ПЕЧАТИ
--------------------------------------------------------------------------------
10.1. GCodeParserService — поддерживаемые команды
  Парсинг строк: удаление комментариев скобок (...) и от ; до конца строки.
  Регулярка команд: [GM] + целое число; параметры [A-Z] + число.
  Реализовано:
    G0, G1 — линейные перемещения с X,Y,Z,E,F
    G20 — unitScale=25.4 (дюймы → внутренне мм через масштаб)
    G21 — unitScale=1.0
    G90 — абсолютные координаты станка
    G91 — относительные
    G92 — сброс текущих X,Y,Z,E в заданные значения
    M82 — абсолютный экструдер
    M83 — относительный экструдер
  Экструзия: флаг IsExtrusion, если длина перемещения > 1e−6 и ΔE>1e−6.
  Не реализовано в парсере: разогрев, вентиляторы, ретракт-манипуляции и прочий
  прикладной G/M-макросный слой — диплом должен явно ограничить класс файлов.

10.2. SurfaceProjectionService
  Проекция опорных маркеров на две оси с max разбросом (аналог локальной
  параметризации кусочно-плоской поверхности).
  Триангуляция Делоне в 2D (инкрементальный алгоритм с супертреугольником и
  тестом описанной окружности — детали реализации в файле).
  Подгонка bounds G-кода к bounds маркерной UV-поверхности с FitMarginRatio=0.72.
  Дробление отрезков: экструзия max 2.5 мм; travel max 8 мм — более плотная
  дискретизация там, где поверхность изгибается между маркерами.
  Нормаль треугольника n=(b−a)×(c−a); выбор стороны относительно preferredSidePoint.
  PathSurfaceLiftMm = SafetyClearanceMm = 4 мм.
  Оценка пропавшего маркера — IDW-смещение с σ=MissingMarkerInfluenceSmoothingMm=90.
  MinMarkersForDeformation=6 (не путать с числом маркеров только для RBF: там ≥3).

10.3. WoundMeshProjectionService
  Треугольники из mesh; MinTriangleArea UV=1e−6; MinMarkersForDeformation=3 (константа
  сервиса); при проекции число вершин должно совпадать с референсным состоянием.

10.4. PrintTrajectoryService
  Длительность хода: Δt = max(1e−4, length/(F/60)), F в мм/мин, по умолчанию 1800.
  SpeedMultiplier ∈ [0.05, 8]. Положение сопла — бинарный поиск по времени и Lerp
  внутри сегмента.

  Загрузка файла G-кода, построение ProjectedPrintPath (маркеры или mesh).

16. ОГРАНИЧЕНИЯ И ОТСУТСТВУЮЩИЕ В КОДЕ МЕТОДЫ (ВАЖНО ДЛЯ ФОРМУЛИРОВОК ДИПЛОМА)
--------------------------------------------------------------------------------
  - Нет cv::findHomography для привязки слоя печати к одной плоскости — используется
